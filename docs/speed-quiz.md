# TASK — GAME 2 `새싹 스피드 퀴즈` 구현

## 1. 작업 목적

MediaPipe Face Detection과 사진 퀴즈를 결합하여 **60초 동안 사진의 정답을 채팅 입력 방식으로 맞히는 GAME 2 `새싹 스피드 퀴즈`**를 구현한다.

정답 판정 결과에 따라 웹캠 속 사용자 얼굴에 씌워진 새싹 캐릭터 표정이 변경되어야 한다.

- 정답: 웃는 표정
- 첫 연속 오답: 우는 표정
- 2회 이상 연속 오답: 화난 표정

본 작업은 기존 웹사이트의 공통 구조와 GAME 1, GAME 3 기능을 유지하면서 **GAME 2 관련 기능만 추가 또는 수정**하는 것을 원칙으로 한다.

# 6. 게임 상태

게임 진행 상태는 최소 다음 네 단계로 분리한다.

```ts
type Stage = "ready" | "countdown" | "playing" | "result";
```

각 상태의 역할:

- `ready`: 게임 설명, 웹캠 시작, 얼굴 감지 확인
- `countdown`: 3초 카운트다운, 정답 입력 차단
- `playing`: 60초 퀴즈 진행
- `result`: 최종 결과 및 리소스 지표 표시

페이지 안에서 위 상태를 전환하되 `/games/game-2` 라우트 구조는 유지한다.

# 11. 문제 순서

게임 시작 시 전체 문제 배열을 한 번 섞는다.

- 한 게임 안에서는 동일 문제를 중복 출제하지 않는다.
- 문제를 모두 사용했는데 시간이 남은 경우 새 순서로 다시 섞어 출제할 수 있다.
- 새로 섞을 때 직전 문제와 동일한 문제가 연속으로 나오지 않게 한다.
- 게임 재시작 시 문제 순서를 다시 섞는다.

문제 이미지가 로딩되지 않은 경우 해당 문제를 건너뛰고 시스템 이벤트 로그에 기록한다.

# 12. 문제 표시

플레이 화면에는 최소 다음 항목을 표시한다.

- 현재 사진 문제
- 남은 시간
- 현재 점수
- 현재 콤보
- 정답 입력창
- 최근 제출 결과 또는 판정 피드백
- 웹캠 영상

사진은 원본 비율을 유지하고 컨테이너 안에서 잘리지 않도록 기본적으로 `object-fit: contain`을 사용한다.

새 문제가 표시될 때마다 정답 입력창에 자동으로 포커스를 이동한다.

# 13. 정답 입력

사용자는 채팅 형태의 입력창에 답을 입력하고 Enter로 제출한다.

제출 규칙:

- 빈 문자열은 제출하지 않는다.
- 입력값 앞뒤의 공백은 제거한다.
- 판정 또는 전환 애니메이션 중 중복 제출을 막는다.
- 한 문제는 한 번만 판정한다.
- 제출 직후 입력값을 비운다.
- 한글 IME 조합 중 Enter가 중복 제출되지 않도록 `isComposing`을 확인한다.

버튼 클릭으로도 제출할 수 있도록 전송 버튼을 제공한다.

---

# 14. 정답 판정

앞뒤 공백을 제거한 입력값과 등록된 정답이 정확히 일치할 때만 정답으로 처리한다.

```ts
const isCorrect = submittedAnswer.trim() === question.answer;
```

다음 변형은 자동으로 정답 처리하지 않는다.

- 내부 띄어쓰기 차이
- 오타
- 구두점 추가
- 영문 대소문자 차이
- 등록되지 않은 약칭 또는 별칭

필요한 별칭은 자동 유사도 판정이 아니라 문제 데이터의 정답을 명시적으로 확장하는 방식으로만 지원한다.

---

# 15. 정답 처리

정답인 경우 다음 작업을 한 번만 수행한다.

1. 캐릭터 표정을 웃는 표정으로 변경
2. 연속 오답 횟수를 0으로 초기화
3. 콤보를 1 증가
4. 점수 계산 및 누적
5. 정답 횟수 증가
6. 응답 시간 기록
7. 성공 피드백 표시
8. 약 350ms 후 다음 문제 이동

정답 피드백 예시:

```text
정답이에요! +130점
3 COMBO
```

350ms 동안에도 전체 60초 타이머는 계속 진행한다.

---

# 16. 오답 처리

오답인 경우 다음 작업을 한 번만 수행한다.

1. 연속 오답 횟수를 1 증가
2. 첫 연속 오답이면 우는 표정으로 변경
3. 2회 이상 연속 오답이면 화난 표정으로 변경
4. 현재 콤보를 0으로 초기화
5. 오답 횟수 증가
6. 응답 시간 기록
7. 정답을 800ms 동안 표시
8. 다음 문제 이동

오답 피드백 예시:

```text
틀렸어요
정답: 한라산
```

오답으로 점수를 차감하지 않는다. 정답 공개 중에도 전체 60초 타이머는 계속 진행한다.

# 17. 캐릭터 표정 규칙

사용할 이미지:

```text
웃음: /game-2/characters/sesac-smile.png
울음: /game-2/characters/sesac-sad.png
화남: /game-2/characters/sesac-angry.png
```

표정 상태:

```ts
type CharacterExpression = "smile" | "sad" | "angry";
```

게임 시작 시 기본 표정은 웃는 표정이다.

표정은 일정 시간이 지나도 기본 표정으로 자동 복귀하지 않는다. **다음 문제의 판정 결과가 나오기 전까지 마지막 판정의 표정을 계속 유지한다.**

예시:

```text
게임 시작 → 웃음
오답 → 울음
다음 문제 출제 → 계속 울음
다시 오답 → 화남
다음 문제 출제 → 계속 화남
정답 → 웃음
다음 문제 출제 → 계속 웃음
```

준비 화면의 수동 표정 선택 UI는 개발 확인 용도로만 취급한다. 실제 게임 진행 중에는 판정 결과가 표정을 결정하며 사용자가 임의로 표정을 변경할 수 없도록 한다.

---

# 18. 얼굴 마스크

기존 GAME 2의 MediaPipe Face Detection 기반 마스크를 유지한다.

- 얼굴 Bounding Box 기준으로 캐릭터 크기 결정
- 사용자 얼굴 전체와 목 위 영역을 충분히 가림
- 눈 위치는 크기 기준으로 사용하지 않음
- 눈 좌표는 고개 기울기 계산에 사용할 수 있음
- 웹캠 좌우 반전 좌표 보정 유지
- `object-fit: cover`에 따른 크롭 보정 유지
- 위치, 크기, 회전에 스무딩 적용

얼굴이 감지되지 않는 동안 캐릭터 마스크는 숨기고 얼굴을 카메라 중앙에 보여달라는 안내를 표시한다.

플레이 중 얼굴을 놓쳐도 60초 타이머와 퀴즈는 멈추지 않는다. 얼굴이 다시 감지되면 마스크를 자동으로 복구한다.

# 19. 점수와 콤보

정답 점수 공식:

```ts
const nextCombo = combo + 1;
const comboBonus = Math.min(nextCombo * 10, 50);
const scoreDelta = 100 + comboBonus;
```

점수 예시:

```text
1 COMBO → 110점
2 COMBO → 120점
3 COMBO → 130점
4 COMBO → 140점
5 COMBO 이상 → 150점
```

오답:

```text
점수 변화 없음
콤보 0으로 초기화
```

별도로 기록할 값:

- 최종 점수
- 현재 콤보
- 최고 콤보
- 정답 수
- 오답 수
- 총 제출 수

# 20. 60초 타이머

게임 제한 시간은 정확히 60초다.

단순히 `setInterval` 호출마다 1초씩 차감하지 않는다. 게임 종료 시각을 저장하고 `performance.now()`를 기준으로 남은 시간을 계산한다.

```ts
const deadline = performance.now() + 60_000;
const remainingMs = Math.max(0, deadline - performance.now());
```

다음 구간에도 타이머는 계속 흐른다.

- 정답 성공 피드백 350ms
- 오답 및 정답 공개 800ms
- 얼굴을 감지하지 못한 시간
- 문제 이미지 로딩 시간

탭이 백그라운드로 이동하거나 렌더링이 지연되어도 실제 경과 시간을 기준으로 종료해야 한다.

---

# 21. 게임 종료

다음 경우 게임을 종료한다.

- 제한 시간 60초 종료
- 사용자가 게임 종료 버튼 클릭

종료 즉시 다음 작업을 수행한다.

1. 추가 입력 및 Enter 제출 차단
2. 진행 중인 피드백 타이머 정리
3. 진행 중인 문제를 미응답으로 두고 결과에서 제외
4. 얼굴 감지 프레임 루프 종료
5. 웹캠 스트림 종료
6. 최종 통계 계산
7. `result` 화면으로 전환

60초가 끝나는 순간 제출 이벤트와 충돌하더라도 한 문제의 결과가 중복 반영되지 않도록 한다.

---

# 22. 결과 데이터

각 제출 기록은 최소 다음 데이터를 포함한다.

```ts
type QuizAttempt = {
  questionId: string;
  submittedAnswer: string;
  correctAnswer: string;
  result: "correct" | "wrong";
  scoreDelta: number;
  totalScore: number;
  comboAfter: number;
  responseTimeMs: number;
  submittedAtMs: number;
};
```

게임 전체 결과:

```ts
type SpeedQuizResult = {
  score: number;
  correctCount: number;
  wrongCount: number;
  accuracy: number;
  maxCombo: number;
  averageResponseTimeMs: number;
  attempts: QuizAttempt[];
};
```

정답률 계산 시 제출하지 않은 마지막 문제는 포함하지 않는다.

---

# 23. 결과 화면

결과 화면에는 최소 다음 항목을 표시한다.

- 최종 점수
- 맞힌 문제 수
- 틀린 문제 수
- 정답률
- 최고 콤보
- 평균 응답 시간
- 평균 FPS
- 평균 얼굴 감지 추론 시간
- 최대 얼굴 감지 추론 시간
- 지원되는 경우 메모리 사용량

결과 화면 동작:

- `다시 하기`: 모든 게임 상태를 초기화하고 준비 화면으로 이동
- `다른 게임`: `/games`로 이동

다시 하기 시 이전 문제 순서, 점수, 콤보, 연속 오답, 답안 기록 및 성능 지표를 모두 초기화한다.

# 24. 리소스 모니터링

게임 중 최소 다음 값을 수집한다.

- 렌더링 FPS
- MediaPipe 추론 횟수
- 최근 추론 시간
- 평균 추론 시간
- 최대 추론 시간
- 가능하면 프레임 처리 시간
- 지원 브라우저에서만 JS 메모리 사용량

브라우저에서 시스템 전체 CPU 사용률을 정확히 측정할 수 없으므로 임의의 CPU 값을 생성하지 않는다.

기존 UI의 `CPU` 표시는 다음 중 하나로 교체한다.

```text
FRAME TIME
INFERENCE
LONG TASKS
```

메모리 API를 지원하지 않는 브라우저에서는 `지원 안 함` 또는 `--`로 표시한다.

- Enter 제출과 전송 버튼 모두 지원
- 판정 결과를 색상만으로 구분하지 않음
- 정답/오답 텍스트와 아이콘을 함께 표시
- 카운트다운과 판정 피드백에 적절한 라이브 영역 사용
- 키보드만으로 게임 진행 가능
- 애니메이션 감소 설정을 존중

# 27. 오류 처리

다음 오류를 화면에서 구분하여 안내한다.

- 카메라 권한 거부
- 웹캠 미지원
- MediaPipe 모델 로딩 실패
- 얼굴 감지 실패
- 문제 데이터 없음
- 문제 이미지 로딩 실패
- 게임 중 카메라 스트림 종료

문제 이미지 하나가 실패한 경우 전체 게임을 중단하지 않고 해당 문제를 건너뛴다. 사용 가능한 문제가 하나도 없으면 게임을 종료하고 오류 안내를 표시한다.

오류 객체나 브라우저 내부 메시지를 사용자에게 그대로 노출하지 않고 이해하기 쉬운 한글 문구로 변환한다.

# 28. 상태 관리 주의사항

- 제출 처리 중 중복 Enter 차단
- 판정 완료 전에 다음 문제로 두 번 이동하지 않음
- React 비동기 상태 갱신에 의존하여 점수 또는 콤보가 한 단계 늦게 계산되지 않게 함
- 타이머와 지연 콜백에서 최신 상태를 참조하도록 함
- 언마운트 후 상태 변경 방지
- 다시 하기에서 이전 타이머와 프레임 루프가 남지 않게 함
- 개발 모드 Strict Mode에서도 카메라와 MediaPipe가 중복 초기화되지 않게 함

# 31. 테스트 항목

## 준비 화면

- 페이지 진입만으로 카메라가 켜지지 않는다.
- 웹캠 버튼 클릭 후에만 권한을 요청한다.
- 얼굴 감지 전에는 게임을 시작할 수 없다.
- 문제 데이터가 없으면 게임을 시작할 수 없다.

## 카운트다운

- `3 → 2 → 1 → START` 순서가 한 번만 실행된다.
- 카운트다운 중 답안을 제출할 수 없다.
- 카운트다운 종료 시 정확히 60초가 시작된다.

## 문제

- 이미지와 정답이 올바르게 연결된다.
- 한 세션에서 문제가 중복되지 않는다.
- 이미지 로딩 실패 시 다음 문제로 안전하게 넘어간다.
- 문제 전환 후 입력창에 자동 포커스된다.

## 정답 판정

- 정확히 일치하는 답만 정답이다.
- 앞뒤 공백은 무시된다.
- 내부 띄어쓰기, 오타 및 구두점 차이는 오답이다.
- 빈 문자열은 제출되지 않는다.
- IME 조합 중 Enter가 중복 제출되지 않는다.

## 점수와 콤보

- 첫 정답은 110점이다.
- 콤보 보너스는 최대 50점이다.
- 오답은 점수를 차감하지 않는다.
- 오답 후 콤보가 0으로 초기화된다.
- 최고 콤보가 정확히 기록된다.

## 표정

- 게임 시작 시 웃는 표정이다.
- 첫 연속 오답 후 우는 표정이다.
- 2회 이상 연속 오답 후 화난 표정이다.
- 정답 후 웃는 표정으로 변경된다.
- 표정은 다음 판정 전까지 유지된다.
- 새 문제가 표시될 때 표정이 자동으로 초기화되지 않는다.

## 피드백

- 정답 피드백은 약 350ms 표시된다.
- 오답 정답 공개는 약 800ms 표시된다.
- 피드백 중 중복 제출이 불가능하다.
- 피드백 중에도 60초 타이머가 계속 흐른다.

## 종료 및 결과

- 60초가 되면 입력이 즉시 잠긴다.
- 종료 시점의 중복 판정이 발생하지 않는다.
- 최종 점수, 정답률 및 최고 콤보가 정확하다.
- 평균 응답 시간이 정확히 계산된다.
- 웹캠과 MediaPipe가 정상적으로 정리된다.
- 다시 하기가 이전 상태를 남기지 않는다.

## 회귀 테스트

- `/` → `/player` → `/games` 흐름이 유지된다.
- GAME 1 동작에 영향이 없다.
- GAME 3 동작에 영향이 없다.
- 브라우저 뒤로가기가 정상 동작한다.
- 다른 게임 버튼이 `/games`로 이동한다.

# 35. 완료 조건

다음 조건을 모두 만족해야 작업 완료로 판단한다.

- 문제 사진과 정답이 데이터로 연결되어 있다.
- 카메라는 사용자 버튼 클릭 후에만 시작된다.
- 얼굴 전체에 새싹 캐릭터가 정상적으로 씌워진다.
- 3초 카운트다운 후 정확히 60초 게임이 진행된다.
- 사용자가 채팅 입력과 Enter로 답안을 제출할 수 있다.
- 정확히 일치하는 답만 정답으로 처리된다.
- 정답과 오답 피드백 시간이 사양과 일치한다.
- 점수와 콤보가 정해진 공식대로 계산된다.
- 첫 오답은 울음, 연속 오답은 화남, 정답은 웃음으로 표시된다.
- 마지막 판정 표정이 다음 판정 전까지 유지된다.
- 게임 종료 후 결과 및 리소스 지표가 표시된다.
- 카메라, 프레임 루프 및 타이머가 정리된다.
- GAME 1과 GAME 3 동작에 회귀가 없다.
- 타입 검사와 린트에 오류가 없다.
